# 可视化质量规范

图表用于降低关系理解成本，而不是装饰文档。作者源只使用 Markdown 友好的 Mermaid、Markdown 表格和文本目录树；不把独立 SVG、Draw.io 或位图作为默认源文件。

## 类型选择

| 要表达的关系 | 默认形式 |
| --- | --- |
| 系统上下文、组件、分层、数据流、因果关系 | Mermaid flowchart，必要时使用 subgraph |
| 调用顺序、协议交互、异步协作 | Mermaid sequence diagram |
| 生命周期、状态转换、异常恢复 | Mermaid state diagram |
| 类、接口与静态关系 | Mermaid class diagram |
| 实体、字段与数据关系 | Mermaid ER diagram |
| 概念及其分支 | Mermaid mindmap |
| 历史演化与里程碑 | Mermaid timeline |
| 阶段、时间和依赖 | Mermaid gantt，仅在三者确实重要时使用 |
| 方案、能力和取舍的重复字段比较 | Markdown 表格 |
| 目录、模块和文件层级 | 文本树 |

## 选择与解释

- 架构、层次、关键流程或状态转换是核心论证且文字难以快速表达时，优先使用合适图表。
- 一张图只回答一个主要问题。复杂系统借鉴 C4 的缩放思想，按解释价值拆成上下文、容器或模块、关键内部机制；不机械绘制固定层数。
- 图前说明它回答的问题；图后解释阅读顺序、关键边界、容易误读处和结论。
- 图中的术语、方向、数据边界与信任边界必须和正文一致。
- 表格只表达重复字段比较，文本树只表达层级；叙事、因果链和长解释不用表格或目录树替代。
- 图表数量由认知负担和解释价值决定，不设最低数量，不为丰富感强加图表。
- 技术和非技术主题都可以绘图；时间线、概念图、因果图和比较表同样适用于非技术内容。

## 档位与画像

- `survey`：优先领域地图、组成关系和简短对比。
- `beginner`：优先单路径流程、最小架构和关键状态。
- `advanced`：加入内部机制、关键时序、状态和典型失败路径。
- `deep-dive`：覆盖主要视角、演化和方案取舍，但避免重复表达。
- `expert`：突出信任边界、数据边界、生产约束、异常路径和替代架构。

这些是倾向而非模板。画像影响图中的抽象层级、术语密度和可省略的基础节点，但不能省略理解核心推理所需的边界。

## Mermaid 验证

- Markdown 保留 `mermaid` fenced code block，保证源码和 Git diff 可读。
- 构建工具可用时必须实际解析并渲染，解析失败即构建失败。
- 构建工具不可用时至少检查代码块闭合、图类型、节点标识和明显结构错误，并披露未完成实际渲染。
- 成功生成仓库离线预览中的内联 SVG，才算完成本仓库 Mermaid 的实际渲染验证。

## 完成检查

- 每张图有明确问题、正确类型和正文解读。
- 关键关系没有因为图过密、跨层或命名漂移而更难理解。
- 正文与图中的组件、状态、流程、方向和边界一致。
- Mermaid 已实际渲染；未验证范围已披露。
