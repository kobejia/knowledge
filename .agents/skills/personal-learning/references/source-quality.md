# 来源质量与证据验证规范

## 目标

用与主张类型匹配、接近事实源头、专业责任明确且可复核的证据支撑文档。不要以引用数量制造可靠感；无法确认的内容应标记不确定性或从正文删除。

正文可以归纳、比较和推论，但可核实事实、关键结论、数据和争议判断必须有可靠依据。作者推论必须说明前提，并与来源中的事实或观点明确区分。

## 主张与首选来源

| 主张类型 | 首选来源 | 主要检查项 |
| --- | --- | --- |
| API、版本、兼容性 | 当前官方文档、标准、发布说明、源码和官方测试 | 版本、日期、实现差异 |
| 设计动机、架构演化 | RFC、设计提案、提交记录、维护者或核心作者一手说明 | 作者参与关系、当时背景、后续变化 |
| 实际行为、边界条件 | 源码、测试用例、可复现实验、官方 issue | 环境、前提、最小复现 |
| 性能 | 原始 benchmark、测试代码、可复现实验 | 硬件、数据规模、预热、统计方法 |
| 学术结论 | 原始论文、系统综述、权威教材 | 研究设计、样本、证据等级、后续研究 |
| 法律、政策、统计 | 法律政策原文、政府或权威机构原始数据 | 生效范围、统计口径、发布日期 |
| 行业实践 | 直接参与者复盘和多个独立案例 | 场景差异、幸存者偏差、利益关系 |
| 专家观点 | 身份可核验的专家一手文章、演讲或访谈 | 专业关系、证据、观点边界 |

官方材料适合证明官方定义、承诺和规则，不自动证明所有生产环境中的实际表现。专家材料适合解释动机和经验，不自动成为事实或共识。

## 来源优先级

1. 原始与官方材料：标准、源码、原始数据、原始论文、法律政策原文和正式机构报告。
2. 直接参与者材料：维护者、标准制定者、核心作者和直接实践者的一手博客、演讲、课程、访谈与复盘。
3. 正式知识载体：信誉良好的专业书籍、大学教材、课程讲义、学术专著和系统综述。
4. 高质量二手解释：作者与编辑责任明确、引用透明的专业文章或媒体内容，仅用于补充解释和发现线索。

主题发源或核心研究社区在国外时，优先回查原语言的一手资料。语言和国家不是质量等级；可靠的中文原始资料与权威译本无需降级，国外博客也必须通过作者、证据和时效检查。

## 内部证据卡

为影响文档核心模型或结论的主张建立内部证据卡。它不必完整写入正文，但生成前应能回答：

```text
结论：
主张类型：
主要来源：
辅助来源或复现实验：
适用版本、时间与环境：
来源是否直接支持：
是否存在冲突：
采用该解释的理由：
置信度与限制：
```

如果来源只支持较弱结论，必须收窄正文措辞，不能把相关性、设计目标、个人经验或单个案例升级成普遍事实。

## 交叉验证

- 核心结论在条件允许时使用两个相互独立的高质量来源，或使用一个直接事实源加可复现实验。
- 单一标准正文、法律原文、官方数据集或源码就是唯一事实源时，不为满足数量机械添加低质量引用。
- 多篇转载同一原文不算独立来源；追溯并引用最初材料。
- 专家观点应标明作者与主题的关系，并区分个人经验、主流解释、研究结论和争议判断。
- 关键内容依赖译文时尽量回查原文；无法回查时说明限制。

## 时效性

- 软件 API、产品能力、兼容性、标准草案、模型、价格、政策、统计和其他快速变化信息必须记录查证日期及适用版本。
- 当前行为优先使用当前官方或原始材料；历史动机可以使用当时的一手资料；稳定原理可以使用经典论文和权威教材。
- 旧资料可以解释历史，但在未重新核对时不能证明当前行为。
- 没有日期、版本或适用范围的材料不得支撑时效性结论。

## 专家材料检查

采用专家博客、分享、课程或访谈前检查：

- 作者是否直接参与项目、标准、研究或相关生产实践；
- 专业经历和身份是否可以独立核验；
- 是否提供数据、源码、引用、实验或完整推理；
- 是否区分事实、个人经验和观点；
- 是否说明版本、环境、样本与限制；
- 是否存在营销、商业利益或立场偏差；
- 结论是否已被后续版本、勘误或研究修正。

知名度、职位和粉丝数量都不是充分证据。即使是维护者，也只应在其参与范围内提高权重。

## 冲突处理

来源冲突时依次检查：

1. 是否使用相同定义和评价指标；
2. 是否对应不同版本、时间或环境；
3. 一个是否描述设计目标，另一个描述实际表现；
4. 研究方法、样本和统计口径是否不同；
5. 是否存在局部案例过度推广或商业利益；
6. 是否有更新材料、勘误、源码或实验可以裁决。

无法消解时，正文应保留主要分歧、各自证据和当前采用某一解释的理由，不得静默拼接或假装存在共识。

## 可复现验证

适合验证的技术结论尽量实际运行：

- API 行为使用最小 Demo；
- 浏览器行为记录浏览器与版本；
- 性能结论记录设备、数据、预热、次数和统计方法；
- 源码机制定位实现或对应测试；
- 示例运行并检查输出和失败边界；
- 图表与正文中的组件、流程和约束保持一致。

最终区分“来源已核实”“实验已复现”“仅静态推演”和“尚未验证”，不得用其中一种冒充另一种。

## 降噪与排除

排除或降级使用：作者与出处不明的文章、无引用转载、内容农场、SEO 拼接文、不可核验的 AI 生成内容、营销软文，以及与当前原始材料冲突却不给出证据的博客。

博客存在陈旧或局部错误时，只使用仍可独立验证的部分，并标明历史或版本边界。延伸阅读只保留原始证据、独特专业经验或高质量系统解释，删除重复、浅表和低置信度链接。

## 大纲与完成审计

`review: true` 时，大纲中的每个核心章节除层级、问题和图表计划外，还应列出：

- 计划使用的主要来源类型；
- 需要核实的关键主张；
- 计划进行的实验或交叉验证；
- 已知分歧或证据缺口。

完成报告提供简洁的来源审计，不机械追求数量，至少说明：

- 使用了哪些主要来源类型；
- 哪些核心结论完成了交叉验证或复现；
- 是否存在单一来源、来源冲突或未验证部分；
- 查证日期、关键版本和实际验证范围。

如果关键结论只有低质量来源、无法处理的严重冲突或无法确认的时效性信息，应缩小结论、显式保留不确定性，必要时停止生成相关段落。
