# 个人学习

## 概述

根据用户明确选择的档位，生成有可靠来源支撑、归类稳定且图表可验证的 Markdown 学习文档。个人背景来自仓库配置，知识结构来自独立索引，稳定的内容规范由本 skill 管理。

## 推荐输入格式

优先引导用户使用以下提示词模板，但不要把格式完整性作为执行前提：

```markdown
## 目标

[希望学习、生成或修改的内容]

## 补充内容

- [参考链接]
- [本地文件或已有文档]
- [背景信息]
- [特殊要求]
```

也接受单行简写，例如：`## 目标：理解 WebAssembly GC；## 补充内容：https://example.com，重点分析运行时架构`。用户只提供自然语言目标时照常进入流程，不强制补写模板。

解析输入时：

- 将“目标”作为任务主线，识别主题、范围、期望产物和需要修改的现有内容。
- 将“补充内容”拆分为链接、本地文件、背景约束和特殊要求；特殊要求影响重点、范围与表达方式，但不能覆盖来源质量、真实性、安全和仓库规则。
- 主动读取用户提供的公开链接，提取与目标相关的正文、作者或机构、发布日期、版本和引用线索；不要只依据搜索摘要、页面标题或 URL 猜测内容。
- 将链接视为用户指定的优先补充材料，而不是自动可信的事实源。按 `references/source-quality.md` 判断它是原始材料、专家一手内容、正式知识载体还是二手解释，并对关键结论继续核验。
- 链接无法访问、需要登录、已失效、只有摘要或内容与目标无关时，说明具体限制；继续使用其他可获得的高质量来源，不得虚构页面内容，也不得绕过访问控制。
- 补充内容相互冲突，或与目标、当前官方材料冲突时，在“理解与消歧”步骤中指出冲突并让用户选择；事实性冲突仍按来源规范调查，不能让用户偏好替代证据。

## 必要准备

1. 使用 `git rev-parse --show-toplevel` 确定仓库根目录。
2. 检查 `<repo>/personal-learning-config.yaml`。
3. 配置缺失时，先说明将从内置模板初始化，再运行 `scripts/init-config.sh <repo>`。
4. 运行 `scripts/validate-config.sh <repo>/personal-learning-config.yaml`。
5. 校验失败时报告具体字段错误；不得静默使用默认值或覆盖现有配置。
6. 读取配置中的用户画像和 `review` 开关，但不得推断配置中没有写明的经验。
7. 检查 `<repo>/personal-learning-knowledge.json`，并运行 `node scripts/validate-knowledge.mjs`。
8. 知识索引缺失或校验失败时停止，报告具体字段、ID 或路径；不得绕过索引直接落盘。

## 必要交互

生成正文前按顺序完成以下交互。只有拼写修正、机械格式化等不改变语义的编辑可以跳过。

每一步需要用户决策时：

- 必须展示带数字编号的选项，并等待用户回复后再进入下一步。
- 用户可以回复编号，也可以直接输入自定义内容。
- 不得在同一回复中跨过多个尚未确认的步骤。
- 通用确认优先使用：
  1. 确认并继续
  2. 返回调整
  3. 自定义输入

### 1. 理解与消歧

- 先综合目标、已成功读取的补充内容、用户背景和现有仓库内容，再进行理解与消歧；不要把链接内容孤立地当成任务目标。
- 主题、范围或产物存在实质不同的解释时，提供 2–3 个简洁、互斥且带编号的解释选项，并提示用户也可直接输入自定义理解；等待选择。
- 不存在实质歧义时，用一至两句话说明对主题和目标的理解，不得要求用户设计目录；随后提供以下选项并等待回复：
  1. 理解正确，继续
  2. 返回调整
  3. 自定义补充

### 2. 选择内容档位

档位必须由用户选择，不得依据配置或画像自动推荐、预选或代替用户决定。正式定义见 `references/editorial-policy.md`。

1. **专家（`expert`）**：聚焦机制、演化、取舍、生产约束、失败模式与前沿问题。
2. **入门（`beginner`）**：建立必要概念、基本用法与最小可用理解。
3. **进阶（`advanced`）**：从会用进入核心机制、关键设计、常见取舍与典型失败。
4. **全面（`deep-dive`）**：系统覆盖基础、机制、演化、证据、主要方案、分歧与边界。
5. **了解（`survey`）**：建立视野地图，说明主要组成、价值与关键问题。

等待用户选择后再继续。

### 3. 判断主题类型

技术主题询问一次并等待用户回答：

1. 需要完整配套实践（可运行 Demo + 配套练习题）
2. 不需要配套实践
3. 自定义输入

用户只提出 Demo 或练习题时，先说明配套实践包含两部分，再用上述编号选项确认是否接受完整实践。非技术主题说明将跳过配套实践，并提供以下选项等待回复：

1. 确认跳过并继续
2. 返回调整主题类型
3. 自定义输入

没有得到肯定回答时，不得生成 Demo 或独立练习题产物。

### 4. 归类与落盘

读取知识索引中的 `classificationMode`。归类只决定文档位置和分类，不决定档位、实践或图表数量。

- `confirm`：根据主题、现有分类和相邻文档给出 2–3 个带编号且互斥的“分类 + 目标路径”候选，并提示用户也可直接输入自定义分类或路径；等待用户选择后再写入。
- `automatic`：存在唯一明确归属时自动生成一个“分类 + 目标路径”结果，但仍须展示结果并提供编号选项：1. 确认并继续；2. 查看其他候选；3. 自定义分类或路径。并列候选、需要新建顶级分类、路径占用或用户指定位置冲突时，改为给出 2–3 个带编号候选。
- 修改已索引文档时默认沿用原归属，但仍须展示当前分类和路径，并提供编号选项等待确认；用户明确要求移动、主题明显改变或索引冲突时重新给出候选。
- 新建或移动文档时同步更新 `personal-learning-knowledge.json`；不得让文件系统与索引漂移。

### 5. 大纲审阅

读取配置中的 `review`：

- `review: true`：完成前述确认后，先结合用户画像、内容档位、主题类型和最终分类梳理正文大纲。大纲应展示章节层级、各章节解决的核心问题、计划使用的关键图表，以及每章的主要来源类型、待核实主张、验证方式和已知证据缺口；此时不得生成正文、Demo 或练习题。提供以下选项并等待用户回复：
  1. 大纲确认，开始生成
  2. 返回调整大纲
  3. 自定义修改意见
- `review: false`：不展示大纲，也不请求大纲确认，直接进入生成流程。这是“每一步需要用户决策时必须确认”的显式例外，仅跳过大纲审阅，不跳过理解、档位、实践和归类确认。

## 生成流程

1. 解析目标和补充内容，读取可访问的链接、目标文件及仓库中的相邻上下文；记录无法访问或无法确认的补充材料。
2. 按 `references/source-quality.md` 评估补充材料并匹配主张与来源类型，为核心结论建立内部证据卡；使用准确、专业、可追溯且与当前版本相符的材料核实时效性事实、专业结论、标准、版本、政策与争议，主动排除陈旧、错误、无依据或低质量转载内容。
3. 档位决定目标；结合完整画像与主题熟悉度调整起点、术语密度、例子和推理跨度，不机械按单字段分支。
4. 根据所选档位与编辑规范选择自然结构，并按可视化规范选择有解释价值的图表，不套用统一目录或固定数量。
5. 按 `review` 开关完成或跳过大纲审阅；`review: true` 且大纲尚未得到确认时停止，不得提前生成任何正文或配套实践。
6. 创建或修改 Markdown；只有用户选择配套实践后，才同时创建 Demo 与配套练习题。
7. 新建或移动文档时更新知识索引；检查 Markdown 结构、元信息、链接与引用位置。
8. 实际运行 Demo，检查控制台、关键行为与边界；无法验证时说明未验证范围。
9. 执行或推演练习步骤，确保问题围绕 Demo、可以作答并提供答案或评价标准。
10. 对齐正文、来源证据、图表、Demo 与练习题中的目标、术语、前提、行为和边界；按来源规范处理冲突、时效性和未验证范围。
11. 从仓库根目录运行 `node scripts/check.mjs`。这是不依赖 npm、pnpm 或 Yarn 的稳定检查入口，负责自动化测试、Skill 配置与目录契约、知识索引和 Markdown 校验，以及离线预览与 Mermaid 构建；不要把运行命令转交给用户。
12. 检查失败时，先判断失败是否由本次变更造成：修复范围内的问题并重跑；对既有或无关失败保留现场并明确报告。检查未通过时不得宣称完成，预览构建失败时不得覆盖旧预览。
13. 检查通过后，报告最终分类、文档路径、档位、统一检查结果，以及来源审计、图表和实践的实际验证范围；没有证据时不得宣称完成。

## 边界

- README 只用于项目介绍，不作为知识地图或编辑手册。
- `personal-learning-config.yaml` 只保存画像和 `review` 开关；不得加入分类模式、目录、索引或档位推荐。
- `personal-learning-knowledge.json` 是分类、目录树与文档索引的唯一事实源。
- 不得重新创建 `EDITORIAL_GUIDE.md` 或 `READER_PROFILE.md`。
- 不得虚构配置或用户输入中没有的框架、语言、行业、项目、观点或学习进度。
- 不得为了凑齐引用或延伸阅读而引入低质量外部内容；来源数量不能替代来源质量。
- 除非用户在交互中选择，否则不得把知识请求扩张成课程、计划或配套实践。
- 正文可以包含少量理论自检题，但不得将其包装成独立练习题产物，也不得用它替代完整实践。
- 保留用户已有修改，避免无关重写。
