# 配套实践质量规范

仅在用户为技术主题选择配套实践后读取本文件。配套实践是一个不可拆分的学习产物：包含可运行 Demo，以及围绕该 Demo 的练习题、答案或评价标准。

## 实践目标

- 明确实践要验证的概念、运行行为、边界、反例或取舍。
- 每个实践只围绕一个主要学习目标，正文、Demo 与练习题共享该目标。
- 使用以下闭环组织实践，而不是把代码和题目简单并排：

```text
运行 -> 观察 -> 推理 -> 修改 -> 验证
```

## Demo

- 构建能够观察目标行为的最小实现。
- 除非框架或依赖本身就是主题，否则优先使用原生 HTML、CSS 和 JavaScript。
- HTML 负责语义，CSS 负责表现，JavaScript 负责行为。
- 命名与正文术语一致，仅在代码无法说明原因时添加简短注释。
- 排除与目标无关的装饰、抽象、分析埋点、认证和生产脚手架。
- 如果不能直接打开 HTML 运行，在 Demo 旁提供启动说明。

## 练习题

- 围绕 Demo 设计观察、解释、预测、调试、修改和边界分析任务。
- 抽象程度、前置知识和难度符合 `beginner`、`survey`、`deep-dive` 或 `expert`。
- 不考查正文未覆盖的知识，也不依赖 Demo 中不存在或尚未验证的行为。
- 选择少量有区分度的问题，不机械追求固定数量。
- 每道题都推动闭环前进，例如先预测修改结果，再实际运行验证。

## 答案与评价

- 每道题提供可核对的答案、解释、预期现象或评分标准。
- 说明答案如何由正文和 Demo 行为推出；必要时解释看似合理的替代答案为何不成立。
- 答案与题目适当分离，使读者能够先作答；可使用 Markdown 折叠块或独立答案章节。
- 修改型任务应说明预期行为或关键检查点，而不只给出最终代码。

## 验证

- 按说明实际启动或打开 Demo。
- 检查初始状态、关键交互、预期状态变化，以及正文涉及的失败或边界情况。
- 检查浏览器控制台中由 Demo 引起的错误和警告。
- 当布局影响结论时检查窄视口和宽视口。
- 实际执行或逐步推演练习操作，确认问题、答案和 Demo 行为一致。
- 确认正文没有承诺 Demo 中不存在的行为。

## 完成检查

- 实践具有一个明确目标，并形成“运行、观察、推理、修改、验证”闭环。
- Demo 按说明可以运行，没有未解释的控制台错误。
- 每道题都依赖正文与 Demo 实际呈现的内容。
- 答案或评价标准完整，难度与所选档位一致。
- 正文、Demo、题目和答案的术语、前提、行为及限制一致。
- 未验证的环境或行为已经披露，没有被报告为完成。
