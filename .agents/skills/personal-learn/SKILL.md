# 个人学习

## 概述

根据用户明确选择的档位，生成有可靠来源支撑、归类稳定且图表可验证的 Markdown 学习文档。个人背景来自仓库配置，知识结构来自独立索引，稳定的内容规范由本 skill 管理。

## 必要准备

1. 使用 `git rev-parse --show-toplevel` 确定仓库根目录。
2. 检查 `<repo>/personal-learn-config.yaml`。
3. 配置缺失时，先说明将从内置模板初始化，再运行 `scripts/init-config.sh <repo>`。
4. 运行 `scripts/validate-config.sh <repo>/personal-learn-config.yaml`。
5. 校验失败时报告具体字段错误；不得静默使用默认值或覆盖现有配置。
6. 读取配置，但不得推断配置中没有写明的经验。
7. 检查 `<repo>/personal-learn-knowledge.json`，并运行 `npm run validate:knowledge`。
8. 知识索引缺失或校验失败时停止，报告具体字段、ID 或路径；不得绕过索引直接落盘。

## 必要交互

生成正文前按顺序完成以下交互。只有拼写修正、机械格式化等不改变语义的编辑可以跳过。

### 1. 理解与消歧

- 主题、范围或产物存在实质不同的解释时，提供简洁、互斥的选项并等待选择。
- 不存在实质歧义时，用一至两句话说明对主题和目标的理解。不得要求用户设计目录。

### 2. 选择内容档位

档位必须由用户选择，不得依据配置或画像自动推荐、预选或代替用户决定。正式定义见 `references/editorial-policy.md`。

- **专家（`expert`）**：聚焦机制、演化、取舍、生产约束、失败模式与前沿问题。
- **入门（`beginner`）**：建立必要概念、基本用法与最小可用理解。
- **进阶（`advanced`）**：从会用进入核心机制、关键设计、常见取舍与典型失败。
- **全面（`deep-dive`）**：系统覆盖基础、机制、演化、证据、主要方案、分歧与边界。
- **了解（`survey`）**：建立视野地图，说明主要组成、价值与关键问题。

等待用户选择后再继续。

### 3. 判断主题类型

技术主题询问一次并等待用户回答：

- 是否需要配套实践（可运行 Demo + 配套练习题）？

用户只提出 Demo 或练习题时，先说明配套实践包含两部分，再确认是否接受完整实践。非技术主题直接跳过实践确认。没有得到肯定回答时，不得生成 Demo 或独立练习题产物。

### 4. 归类与落盘

读取知识索引中的 `classificationMode`。归类只决定文档位置和分类，不决定档位、实践或图表数量。

- `confirm`：根据主题、现有分类和相邻文档给出 2–3 个互斥的“分类 + 目标路径”候选，允许用户自行输入；确认后再写入。
- `automatic`：存在唯一明确归属时自动处理；并列候选、需要新建顶级分类、路径占用或用户指定位置冲突时才请求确认。
- 修改已索引文档时沿用原归属，除非用户明确要求移动、主题明显改变或索引冲突。
- 新建或移动文档时同步更新 `personal-learn-knowledge.json`；不得让文件系统与索引漂移。

## 必读参考

- 始终读取：`references/editorial-policy.md`
- 始终读取：`references/markdown-quality.md`
- 始终读取：`references/visual-policy.md`
- 仅在用户选择配套实践后读取：`references/practice-quality.md`

## 生成流程

1. 编辑前读取目标文件及仓库中的相邻上下文。
2. 使用一手或权威来源核实时效性事实、专业结论、标准、版本、政策与争议。
3. 档位决定目标；结合完整画像与主题熟悉度调整起点、术语密度、例子和推理跨度，不机械按单字段分支。
4. 根据所选档位与编辑规范选择自然结构，并按可视化规范选择有解释价值的图表，不套用统一目录或固定数量。
5. 创建或修改 Markdown；只有用户选择配套实践后，才同时创建 Demo 与配套练习题。
6. 新建或移动文档时更新知识索引；检查 Markdown 结构、元信息、链接与引用位置。
7. 实际运行 Demo，检查控制台、关键行为与边界；无法验证时说明未验证范围。
8. 执行或推演练习步骤，确保问题围绕 Demo、可以作答并提供答案或评价标准。
9. 对齐正文、图表、Demo 与练习题中的目标、术语、前提、行为和边界。
10. 从仓库根目录运行 `npm run check`。该统一脚本负责自动化测试、Skill 配置与目录契约、知识索引和 Markdown 校验，以及离线预览与 Mermaid 构建；不要把运行命令转交给用户。
11. 检查失败时，先判断失败是否由本次变更造成：修复范围内的问题并重跑；对既有或无关失败保留现场并明确报告。检查未通过时不得宣称完成，预览构建失败时不得覆盖旧预览。
12. 检查通过后，报告最终分类、文档路径、档位、统一检查结果，以及图表和实践的实际验证范围；没有证据时不得宣称完成。

## 边界

- README 只用于项目介绍，不作为知识地图或编辑手册。
- `personal-learn-config.yaml` 只保存画像；不得加入分类模式、目录、索引或档位推荐。
- `personal-learn-knowledge.json` 是分类、目录树与文档索引的唯一事实源。
- 不得重新创建 `EDITORIAL_GUIDE.md` 或 `READER_PROFILE.md`。
- 不得虚构配置或用户输入中没有的框架、语言、行业、项目、观点或学习进度。
- 除非用户在交互中选择，否则不得把知识请求扩张成课程、计划或配套实践。
- 正文可以包含少量理论自检题，但不得将其包装成独立练习题产物，也不得用它替代完整实践。
- 保留用户已有修改，避免无关重写。
