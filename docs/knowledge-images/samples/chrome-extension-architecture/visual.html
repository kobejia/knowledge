Chrome Extension 不是“获得更多 API 的网页”

Manifest V3 · 运行时模型 · 权限边界 · 可恢复状态
它是一个跨多个生命周期与信任区的事件驱动系统。真正决定质量的是：最小权限、消息协议、可恢复状态、特权隔离。

01 低信任与短生命周期

网页主世界页面代码不可信，DOM 可随时重建
↓ DOM / 显式桥接
Content Script靠近页面，只做适配与输入清理，不持有高权限
Popup / Side PanelUI 各有生命周期，不应成为唯一状态源

02 特权协调中心

版本化消息协议 · 来源验证 · 结构化错误
↓ 只映射到明确允许的能力
Service Worker事件协调、Chrome API、跨标签状态。它权限高，但会被终止，不是常驻服务器。
↓ 事件到达时重建最小上下文
幂等任务阶段pending → running → succeeded / failed，中断后可安全重试

03 持久化与外部能力

chrome.storage / IndexedDB真相来源：用户配置、业务实体、任务阶段
Chrome API / Network只能在 manifest 与当前用户授权的能力范围内使用
Manifest同时是能力声明、攻击面、用户授权和商店审核边界
权限最小化

从用户动作反推 API 和 host 范围，优先 activeTab 与 optional permission。

消息协议化

消息是跨信任边界的 RPC，不是普通函数调用。

状态可恢复

进程不是状态所有者；内存 Map 只能作为可重建的缓存。

特权隔离

不让低信任输入组合成任意 URL、任意注入或敏感数据泄露。

核心记忆点： 这是一个小型分布式系统 + capability security 模型，而不是 popup + background.js + content.js 三个文件。
