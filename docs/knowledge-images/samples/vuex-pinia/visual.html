Vuex vs Pinia：同源不同构

底层机制相似，上层架构与开发体验显著不同
共同底层：响应式系统 + 应用级依赖注入

两者都通过 app.use() 将根管理器注入组件树，并依靠 Vue 响应式机制驱动视图更新。变化的不是这一原理，而是 Store 如何组织和修改。

Vuex

单一状态树与中心化模块
存储结构树形嵌套

所有状态属于单一 state，模块需命名空间管理。

修改流程State → Mutation → Action

同步变更也要定义 mutation，调试边界清晰但样板较多。

模块化中心注册

根 Store 显式导入并组织子模块。

TypeScript额外类型工作

常需 InjectionKey、泛型和手工封装。

VS

Pinia

扁平 Store Map 与去中心组合
存储结构独立 Store

每个 Store 用唯一 id 存入 Map，无嵌套路径。

修改流程Action 直接改 State

同步与异步逻辑内聚，减少 mutation 仪式。

模块化按需注册

Store 可独立定义、相互组合，无固定层级。

TypeScript原生推导

函数式 API 自动推导 state、getters 和 actions。

Vue 2 维护 / 旧架构迁移继续使用 Vuex 可避免无必要的架构震荡。
Vue 3 新项目优先 Pinia：保留同一响应式基础，降低组织与类型成本。
核心判断： Pinia 不是更换响应式原理，而是用 Vue 3 的能力重构状态管理的上层组织方式。
