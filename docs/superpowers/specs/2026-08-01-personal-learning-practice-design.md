# Personal Learn 实践闭环设计

## 背景

当前 `personal-learning` 将 Demo 与练习题作为两个可独立选择的附加产物，使用两次确认和两份专项规范。这种设计允许只生成 Demo 或只生成练习题，但两者的学习价值没有形成稳定连接：Demo 容易退化为展示，练习题也可能脱离可观察行为。

本设计将两者合并为一个“配套实践”能力。实践通过可运行 Demo 提供观察对象，通过练习题引导解释、调试、修改和验证，形成完整学习闭环。

## 目标

- 技术主题只确认一次是否需要配套实践。
- 选择实践后始终同时生成 Demo 与围绕 Demo 的练习题。
- 练习题提供可核对的答案、预期现象或评价标准。
- 将 Demo 与练习题的规范合并为 `practice-quality.md`。
- 删除只生成 Demo 或只生成练习题的交互、路由和评估分支。
- 非技术主题继续跳过实践确认。
- 保持 skill、配置、档位、Markdown 规范与编辑原则不变。

## 非目标

- 不让所有技术文档默认生成实践。
- 不为非技术主题生成 Demo。
- 不禁止正文中出现少量理论自检题。
- 不把理论自检题视为独立练习题产物。
- 不修改配置 schema、档位定义或仓库目录结构。
- 不扩展 Demo 支持的技术栈或引入新的构建工具。

## 交互调整

原流程：

1. 是否需要 Demo？
2. 是否需要练习题？

新流程：

1. 是否需要配套实践（可运行 Demo + 配套练习题）？

规则：

- 技术主题询问一次并等待回答。
- 用户选择“需要”后，加载实践规范并生成完整实践。
- 用户选择“不需要”后，不生成 Demo 或独立练习题产物。
- 非技术主题跳过该问题。
- 用户仅提出“需要 Demo”或“需要练习题”时，说明实践产物包含两部分，并确认是否接受完整实践；不得静默只生成其中一部分。

## 实践闭环

每个实践围绕正文中的一个明确目标组织：

```text
运行 Demo
  -> 观察关键行为
  -> 解释运行模型或原因
  -> 修改参数、状态或实现
  -> 预测结果
  -> 再次运行并验证
  -> 分析边界或失败模式
```

Demo 与练习题必须共享术语、前提和目标。练习题不能依赖 Demo 中不存在或尚未验证的行为，Demo 也不能包含正文和练习均不使用的装饰性功能。

## Practice 规范内容

### 目标

- 明确实践验证的概念、运行行为、边界、反例或取舍。
- 每个实践只围绕一个主要学习目标。

### Demo

- 构建能够观察目标行为的最小实现。
- 除非框架或依赖本身就是主题，否则优先使用原生 HTML、CSS 和 JavaScript。
- 保持 HTML、CSS、JavaScript 职责清楚。
- 排除与学习目标无关的装饰、抽象和生产脚手架。

### 练习题

- 主要围绕 Demo 设计观察、解释、调试、预测、修改和边界分析任务。
- 难度匹配 `beginner`、`survey`、`deep-dive` 或 `expert`。
- 不考查正文未覆盖的知识或未经验证的 Demo 行为。
- 每题具有答案、预期现象或评价标准。

### 验证

- 实际启动 Demo，检查初始状态、关键交互、状态变化和相关边界。
- 检查浏览器控制台，以及与结论有关的视口。
- 实际执行或人工推演练习步骤，确保答案与 Demo 行为一致。
- 无法验证的部分必须披露。

## 正文理论自检题

正文可以包含少量无需 Demo 的概念检查或思考问题，但它们：

- 只作为正文表达的一部分；
- 不触发 `practice-quality.md`；
- 不建立独立练习文件或题库；
- 不替代用户明确选择的完整实践。

## 测试策略

按 RED-GREEN-REFACTOR 修改现有 skill。

### RED

先修改测试并确认失败：

- 结构测试要求 `practice-quality.md` 存在。
- 结构测试要求两个旧 reference 不存在。
- `SKILL.md` 只包含一次实践确认，不再包含两个独立问题。
- `SKILL.md` 只路由到 `practice-quality.md`。
- eval 不得包含只生成 Demo 或只生成练习题的预期。

### GREEN

修改 `SKILL.md`，创建实践规范，删除旧 reference，并更新评估场景。运行相同测试直到通过。

### REFACTOR

检查合并后的规范是否存在简单拼接造成的重复，确保实践闭环、验证要求和失败披露只定义一次。

## 评估场景调整

保留六类主要场景，但将技术附加产物改为：

- 技术主题尚未说明实践：询问一次是否需要完整实践。
- 技术主题选择实践：生成 Demo 与配套练习题并验证闭环。
- 技术主题拒绝实践：两者都不生成。
- 用户只要求 Demo：解释完整实践边界并请求确认。
- 用户只要求练习题：解释完整实践边界并请求确认。
- 非技术主题：跳过实践确认。

## 完成标准

- `SKILL.md` 仅询问一次是否需要配套实践。
- `practice-quality.md` 成为实践规范的唯一入口。
- 两个旧 reference 已删除，且不存在残留路由。
- 选择实践时 Demo 与练习题始终同时生成。
- 练习题围绕 Demo 构成运行、观察、推理、修改和验证闭环。
- 拒绝实践或非技术主题不会生成 Demo 或独立练习题。
- 配置、结构、shell 语法、评估 JSON、本地 Markdown 链接与 `git diff --check` 全部通过。
