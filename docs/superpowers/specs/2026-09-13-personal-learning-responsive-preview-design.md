# Personal Learning 响应式预览页设计

日期：2026-09-13

状态：已完成视觉方向确认，等待书面评审

## 1. 目标

重新设计 `personal-learning-preview.html` 的阅读体验，使同一份静态知识预览在 PC 与 H5 上都能高效使用。

核心目标：

- PC 同时提供知识文库、文章正文和本文目录。
- H5 把正文放在首位，目录只在需要时出现。
- 中文长文、代码、宽表格和 Mermaid 图都保持可读。
- 保留现有知识内容、分类结构和文档链接。
- 不增加前端框架、图标库或运行时依赖。
- 支持浅色与深色模式，并满足基础无障碍要求。

## 2. 已确认方向

页面采用“专注阅读器”方向。

Design Read：这是面向个人技术学习者的长文阅读页，视觉语言克制、编辑化、工具感明确。重点是持续阅读、目录定位和代码可读性。

设计旋钮：

- `DESIGN_VARIANCE: 5`。PC 使用三栏结构，H5 明确收敛为单栏。
- `MOTION_INTENSITY: 3`。仅保留状态切换与操作反馈，不使用自动动画。
- `VISUAL_DENSITY: 4`。目录保持紧凑，正文保持足够留白。

视觉基础采用原生 HTML、CSS 和 JavaScript。页面不是营销落地页，不引入外部设计系统。现有静态生成架构足以支持本次目标。

## 3. 当前页面审计

### 3.1 当前结构

当前预览由 `scripts/lib/render-preview.mjs` 生成，`personal-learning-preview.html` 是构建产物，不应手工编辑。

现有页面包含：

- 左侧分类树。
- 中间文章正文。
- 基于文档 ID 的 URL hash 切换。
- 分类展开与收起。
- 代码块、表格、引用和 Mermaid 图的基础样式。

### 3.2 当前问题

- 小于 760px 时，完整分类树被放到正文上方。用户需要经过很长的目录才能开始阅读。
- PC 只有文库目录和正文，没有本文目录，长文章内定位成本高。
- 文章宽度最高 920px，中文长句在宽屏上容易形成过长行宽。
- H5 的标题、正文、代码、表格和图表只有基础缩放，没有针对阅读任务分别处理。
- 页面只支持浅色模式。
- 当前交互缺少跳到正文、当前章节、移动端目录对话框和焦点回归。
- 视觉层级主要依赖边框，章节节奏和阅读层级不够清晰。

### 3.3 保留内容

- `personal-learning-knowledge.json` 中的分类与文档关系。
- Markdown 转换后的文章 HTML。
- 现有 `#document-id` 深链接。
- 分类展开与收起能力。
- 文档切换后更新页面标题的行为。

## 4. 信息架构

页面由五个稳定区域组成：

1. 跳到正文链接。
2. 知识文库导航。
3. 移动端阅读工具栏。
4. 文章正文。
5. 本文目录与移动端目录对话框。

建议生成后的语义结构：

```html
<a class="skip-link" href="#document-view">跳到正文</a>
<div class="app-shell">
  <aside class="library-sidebar" aria-label="知识文库">...</aside>
  <header class="mobile-toolbar">...</header>
  <main id="document-view" tabindex="-1">
    <article></article>
  </main>
  <nav class="article-outline" aria-label="本文目录">...</nav>
</div>
<dialog class="mobile-sheet" aria-label="阅读目录">...</dialog>
```

文章正文仍然通过已有的内嵌知识数据渲染。正文渲染完成后，再生成本文目录并增强表格与宽图容器。

## 5. 响应式布局

### 5.1 大屏 PC

适用范围：`1200px` 及以上。

- 页面使用三栏 CSS Grid。
- 左栏为知识文库导航，建议宽度 `clamp(260px, 20vw, 320px)`。
- 中栏为弹性正文区域，文章本身最大宽度 `760px`。
- 右栏为本文目录，建议宽度 `clamp(200px, 16vw, 260px)`。
- 左右栏使用 `position: sticky`、`height: 100dvh` 和独立纵向滚动。
- 页面正文保持单一主滚动容器，避免嵌套正文滚动。

### 5.2 中等屏幕

适用范围：`768px` 至 `1199px`。

- 页面使用知识文库与正文两栏。
- 右侧本文目录隐藏。
- 正文顶部提供“本文目录”按钮，打开与 H5 相同的目录对话框。
- 正文最大宽度保持 `760px`，不因为右栏缺失而无限变宽。

### 5.3 H5

适用范围：`0` 至 `767px`。

- 页面使用严格单栏布局。
- 桌面知识文库与本文目录都不进入正文流。
- 顶部阅读工具栏使用 `position: sticky`，高度约 `56px`。
- 工具栏左侧打开知识文库，右侧打开本文目录。
- 正文左右边距为 `18px`，底部保留安全区空间。
- 使用 `min-height: 100dvh`，不使用 `100vh`。
- 所有主要操作目标至少为 `44px`。

## 6. 移动端目录对话框

移动端使用一个原生 `dialog`，视觉表现为底部抽屉。

抽屉内有两个标签：

- 知识文库：显示现有分类树。
- 本文目录：显示当前文章的章节列表。

行为规则：

- 从工具栏打开时，默认显示对应标签。
- 点击遮罩、关闭按钮或按 Esc 可以关闭。
- 关闭后，焦点回到触发按钮。
- 打开时使用浏览器历史状态。按浏览器返回键优先关闭抽屉，不直接离开当前文章。
- 切换文章后关闭抽屉、滚动到正文顶部，并把焦点移到文章标题。
- 切换章节后关闭抽屉，并把章节滚动到吸附工具栏下方。
- 动画只使用 `transform` 和 `opacity`。
- `prefers-reduced-motion: reduce` 下立即切换，不播放位移动画。

## 7. URL 与章节定位

现有文档链接保持不变：

```text
#processes-and-threads
```

新增章节链接格式：

```text
#processes-and-threads/先记住一个模型
```

实现规则：

- 第一个路径段为文档 ID，第二个路径段为编码后的章节 ID。
- 旧的单段 hash 继续正常工作。
- 标题 ID 根据标题文本确定性生成。
- 标题 ID 保留 Unicode 字母与数字，把空白转为普通连字符，并移除其他标点。
- 同名标题按出现顺序追加 `-2`、`-3`。
- 路由处理器只在文档 ID 改变时重新渲染文章。同一文档内切换章节不重复写入正文。
- 滚动阅读时只更新本文目录的 `aria-current`，不持续改写 URL，也不制造浏览历史噪音。

当前章节使用 `IntersectionObserver` 计算，不注册逐帧 `scroll` 事件。

## 8. 视觉系统

### 8.1 色彩

页面采用冷灰中性色与松石绿单一强调色。

浅色模式核心值：

- 页面背景：`#f3f6f5`
- 正文纸面：`#fbfcfb`
- 主要文字：`#172c33`
- 次要文字：`#607178`
- 分隔线：`#d7e0e1`
- 强调色：`#176b63`
- 强调浅底：`#e5f1ef`

深色模式使用相同色相关系：

- 页面背景：`#10191d`
- 正文纸面：`#162227`
- 主要文字：`#e7efed`
- 次要文字：`#a9b6b7`
- 分隔线：`#2c3e43`
- 强调色：`#73c4b5`
- 强调浅底：`#203c3a`

一个时刻只应用一种全局主题，不按章节翻转主题。默认跟随 `prefers-color-scheme`。

### 8.2 主题控制

- 页面提供“自动、浅色、深色”三态切换。
- 初始值为自动。
- 手动选择保存在 `localStorage`。
- 如果存储不可用，页面继续使用系统偏好，不显示阻塞错误。

### 8.3 字体

不增加字体资源，使用系统字体：

```css
system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif
```

代码使用系统等宽字体：

```css
ui-monospace, SFMono-Regular, Menlo, Monaco, Consolas, monospace
```

### 8.4 字号与行宽

- PC 正文：`17px / 1.85`。
- H5 正文：`17px / 1.8`。
- PC 一级标题：使用 `clamp(34px, 4vw, 46px)`，行高约 `1.2`。
- H5 一级标题：使用 `clamp(28px, 8vw, 34px)`，行高约 `1.25`。
- 二级标题不使用整行底边，通过字号、字重和章节间距建立层级。
- 正文最大宽度为 `760px`。

### 8.5 形状规则

- 内容表面使用 `12px` 圆角。
- 操作控件使用 `8px` 至 `10px` 圆角。
- 按钮不使用全胶囊形状。
- 普通正文区不包裹在卡片中。

## 9. 长文组件

### 9.1 链接

- 链接同时使用强调色与下划线，不能只依赖颜色。
- 下划线与文字保留适当距离，避免中文笔画拥挤。
- 外部链接行为保持当前页面逻辑，不强制新窗口。

### 9.2 引用

- 使用强调色左边界和浅色背景。
- 保持正文级字号，不使用营销式大号引语。
- 深色模式使用相同强调色关系，不翻转为亮色卡片。

### 9.3 代码

- 代码块保持深色实底，浅色与深色页面使用同一材料语言。
- H5 允许代码块横向滚动。
- H5 可让代码背景延伸到正文边缘，但文字仍与正文基线对齐。
- 行内代码使用弱对比底色，并保持 WCAG AA 对比。

### 9.4 表格

- 保留原生 `table` 语义。
- 运行时给表格增加单独的横向滚动容器。
- 表头使用弱底色，行之间只使用单条分隔线。
- 不给每个单元格添加完整方格边框。
- H5 不压缩表格文字，不让页面主体横向滚动。

### 9.5 Mermaid 图和图片

- 图片默认 `max-width: 100%`、`height: auto`。
- 图表容器使用中性纸面、单层边框和独立横向滚动。
- 运行时根据 SVG `viewBox` 判断宽图。宽图在 H5 保留最低可读宽度，由容器横向滚动。
- Mermaid 生成的内嵌白色背景不做反色滤镜，避免破坏语义色和文字可读性。

## 10. 文档切换与本文目录

文档切换流程：

1. 解析 URL hash。
2. 找到目标文档，找不到时回退到首篇文档。
3. 把文章 HTML 写入 `article`。
4. 给文章标题和章节补充确定性 ID。
5. 包装宽表格并标记宽图。
6. 根据 `h2` 和 `h3` 生成本文目录。
7. 更新知识文库中的当前链接状态。
8. 更新 `document.title`。
9. 如果 URL 包含章节 ID，则定位章节；否则回到正文顶部。
10. 把焦点放到文章标题或正文容器。

当前章节高亮不改变文档内容。重新选择同一篇文档时不重复渲染，避免丢失当前阅读位置。

## 11. 无障碍

- 页面提供跳到正文链接。
- 知识文库、正文、本文目录使用明确的 landmark。
- 当前文档和当前章节使用 `aria-current`。
- 分类按钮继续使用 `aria-expanded`。
- 对话框使用原生 `dialog`，并提供可读标题。
- 移动端标签使用正确的 tab 语义和键盘行为。
- 所有按钮都有可见文本，不依赖仅图标操作。
- 键盘焦点使用高对比轮廓，不被吸附栏遮挡。
- 标题使用 `scroll-margin-top`，章节定位后不会被工具栏盖住。
- 文本与交互控件满足 WCAG AA 对比度。
- 主要点击区域至少为 `44px`。

## 12. 状态与错误处理

知识数据直接内嵌在静态 HTML 中，没有异步加载过程，因此不添加伪造的加载动画或骨架屏。

需要覆盖的状态：

- 正常文章状态。
- URL 指向不存在文档时的安全回退状态。
- 知识索引没有任何文档时的空状态。
- 文章没有 `h2` 或 `h3` 时，本文目录显示“本文没有可跳转章节”，不显示空白栏。
- `localStorage` 不可用时的主题回退。
- 浏览器不支持 `dialog.showModal()` 时，使用普通固定定位面板作为降级。

## 15. 性能边界

- 不增加远程字体、图片请求或第三方 JavaScript。
- 不使用逐帧滚动监听。
- 章节观察使用一个 `IntersectionObserver`，文档切换时先断开旧实例。
- 只在移动端对话框上使用 `transform` 和 `opacity` 过渡。
- 避免给滚动容器使用滤镜、噪点或大面积阴影。
- 保留当前内嵌知识数据架构，因此初始 HTML 体积不会在本轮显著下降。

## 16. 风险与回退

### 风险

- 当前预览文件包含大量内嵌文章和 SVG，生成结果体积较大，任何模板错误都会影响全部文章。
- 新章节路由需要同时兼容旧的文档 hash。
- Mermaid SVG 带有内联样式，深色页面中不能简单反色。
- 移动端对话框与浏览器历史结合时容易出现重复返回或关闭状态不一致。

### 控制措施

- 只修改生成器与对应测试，再统一重新生成产物。
- 在路由处理器中区分文档变化和章节变化。
- 对 Mermaid 使用中性独立画布，不改写其内部语义色。
- 抽屉历史只记录打开状态，不把标签切换写入历史。
- 保留现有构建命令作为单一生成入口。

### 回退

改动集中在 `render-preview.mjs`、预览构建测试和生成产物。回退时恢复这三个范围即可，不影响 Markdown、知识索引或其他仓库内容。

## 17. 验收标准

- `1440px` 下同时显示知识文库、正文和本文目录。
- `1024px` 下正文保持可读宽度，右侧本文目录不挤压正文。
- `390px` 与 `360px` 下，正文前方不再出现完整分类树。
- H5 正文字号不小于 `17px`，主要操作目标不小于 `44px`。
- 页面主体在所有检查视口没有横向溢出。
- 宽表格、代码和宽图在自己的容器内可横向滚动。
- 旧的 `#document-id` 地址仍能打开正确文章。
- 新的章节地址可以打开正确文章并定位章节。
- 移动端可以在知识文库与本文目录之间切换。
- 抽屉支持遮罩、Esc 和浏览器返回关闭，并正确恢复焦点。
- 浅色与深色模式保持相同信息层级和单一强调色。
- 键盘用户可以跳到正文、切换文档并使用本文目录。
- 所有现有自动检查通过。
- PC 与 H5 浏览器渲染检查通过。
