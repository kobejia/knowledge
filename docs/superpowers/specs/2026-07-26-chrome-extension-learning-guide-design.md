# Chrome Extension 四周集训营设计说明

## 目标

为具备熟练前端基础、尚未系统学习 Chrome Extension 的用户，生成一份从快速入门到掌握架构精髓的中文集训营文档。

集训营以 Manifest V3 为主线，不写成 API 百科。它要帮助用户建立运行时心智模型，能够独立设计、调试、测试和发布生产级插件，并理解权限、安全、隐私与 Chrome Web Store 的约束。

## 读者与学习条件

- 熟悉 HTML、CSS 和现代 JavaScript。
- 具备日常前端开发经验。
- 不需要重复讲解 DOM、Promise、ES Modules 等基础语法。
- 默认投入为工作日每天 1–2 小时，共 4 周、20 个训练日。
- 周末用于复盘、补进度或完成自由挑战，不强制增加新知识。
- 学习目标覆盖网页增强、效率工具、Side Panel、DevTools、网络能力、工程化与发布。

## 教学方式

采用螺旋式项目驱动：

1. 先建立 Manifest V3、运行上下文、生命周期和权限边界的整体心智模型。
2. 用最小可运行插件验证加载、调试和基本 API。
3. 通过两个小项目和一个综合毕业项目，反复使用消息通信、存储、权限和多上下文协作。
4. 每一轮在已有实践上增加更深的安全、性能、错误恢复和生产约束。
5. 最后提炼可迁移的架构原则，而不是重复罗列 API。

## 文档结构

### 1. 开篇与使用方式

- Chrome Extension 能解决什么问题。
- 本指南明确不重复讲解的前端基础。
- 如何结合阅读、编码、验证和个人记录使用本指南。
- 目标版本、Manifest 版本和资料查证日期。

### 2. 全局心智模型

- Extension 不是一个长期运行的普通网页应用。
- Manifest 的声明式角色。
- Extension Pages、Popup、Side Panel、Content Script、页面主世界和 Extension Service Worker。
- 不同上下文的生命周期、权限、可访问 API 和数据边界。
- Isolated World 与页面主世界的区别。
- 消息通信和共享状态在架构中的位置。

这一部分应包含一个简洁的 Mermaid 架构图。

### 3. 最小可运行插件

- 精简目录结构。
- 完整可复制的 `manifest.json`、Popup、Content Script 和 Service Worker 示例。
- 在 Chrome 中加载未打包扩展。
- 调试不同运行上下文的方法。
- 常见加载和生命周期错误。

### 4. 核心能力深入

围绕真实场景解释，而不是逐个翻译 API：

- Messaging：一次性消息、长连接、上下文边界和错误处理。
- Storage：不同存储区域、配额、同步和状态一致性。
- Tabs 与 Scripting：何时注入、用户手势与权限。
- Permissions 与 Host Permissions：最小授权和可选权限。
- Commands、Context Menus、Notifications。
- Side Panel：长时交互界面与后台协作。

### 5. 高级与生产能力

- `declarativeNetRequest` 的声明式网络规则和适用边界。
- Offscreen Document 的使用条件与生命周期。
- DevTools Extension 的组成和调试对象。
- 跨域请求与扩展页面的网络权限。
- Content Security Policy 和远程托管代码限制。
- Service Worker 休眠、状态恢复、定时任务和幂等设计。
- 性能、日志、错误诊断与版本迁移。

### 6. 安全、隐私与发布

- 权限最小化。
- Content Script、页面输入和消息内容都视为不可信。
- XSS、DOM 注入、消息伪造和数据泄露风险。
- 用户数据、隐私披露和 Chrome Web Store 审核思维。
- 打包、版本号、商店材料、发布与更新流程。

### 7. 工程化与测试

- TypeScript 和模块边界。
- 构建工具的选择原则，不绑定未经必要的框架。
- 单元测试适合覆盖什么。
- 如何用自动化浏览器加载插件并做端到端测试。
- 最小 CI 检查、静态检查和打包验证。

### 8. 两个小项目与一个毕业项目

1. **页面洞察助手**：选取页面内容、提取结构化信息、保存结果。
2. **跨页面研究工作台**：Side Panel、标签页协作、持久化和快捷键。
3. **生产级开发者工具插件**：DevTools、网络规则、权限控制、测试和发布。

前两个项目分别训练网页增强和长时交互界面。第三个是贯穿第 3–4 周的综合毕业项目，需要形成可以演示的完整闭环。

每个项目包含目标、功能范围、技术重点、验收标准和可选挑战，不规定机械的功能数量。

### 9. 四周集训计划

集训共 20 个训练日。每天按照“理解 → 编码 → 验证 → 个人记录”推进，并给出今日机制、最小代码、实战任务、可观察结果、常见失败和完成标准。

1. **第 1 周：页面洞察助手**

   Manifest V3、运行上下文、最小插件、Content Script、隔离世界、Popup、消息通信与基本调试。

2. **第 2 周：跨页面研究工作台**

   Extension Service Worker、Storage、Tabs、Scripting、Permissions、Commands、Context Menus、Side Panel 和跨上下文状态。

3. **第 3 周：DevTools 毕业项目骨架**

   DevTools Extension、`declarativeNetRequest`、Offscreen Document、安全模型、状态恢复和错误诊断。

4. **第 4 周：生产化与毕业验收**

   TypeScript、工程化、自动化测试、性能、打包、商店发布准备、项目演示和个人架构总结。

周末只安排复盘清单、补课建议和自由挑战，不把周末任务计入毕业的硬性要求。

### 10. 精髓总结

归纳真正需要内化的原则：

- 上下文之间通过契约协作。
- 后台不是常驻进程。
- 权限是产品设计的一部分。
- 声明式能力优先于持续运行的命令式逻辑。
- 外部页面和跨上下文消息都属于不可信输入。
- 可恢复状态比内存状态更可靠。
