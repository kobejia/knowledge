# 个人知识库设计说明

## 目标

把本仓库建设成个人学习领地：由用户提出学习想法，AI 协助研究和生成初稿，用户通过判断、查证、实践和复习，将材料逐步转化为自己的知识。

仓库首先服务于个人学习，同时保持对其他读者友好。它不是未经筛选的 AI 内容集合，也不以文档数量作为成功标准。

## 设计原则

1. 内容按知识领域归档，学习状态在首页集中展示。
2. AI 初稿与已经验证、真正内化的知识必须明确区分。
3. 文档结构服从主题，不机械套用统一章节。
4. 只创建实际需要的目录，不预建空分类。
5. 当前采用轻量文件约定，不引入生成脚本或复杂管理系统。

## 仓库结构

```text
knowledge/
├── README.md
├── KNOWLEDGE_GUIDE.md
├── inbox.md
├── vue/
│   └── vuex-pinia.md
└── docs/
    └── superpowers/
        └── specs/
```

- `README.md`：知识库首页，说明定位、学习原则、知识地图、学习看板和使用入口。
- `KNOWLEDGE_GUIDE.md`：记录人机协作、文档元信息、成熟度和质量要求。
- `inbox.md`：快速记录尚未展开的学习想法。
- 主题目录：只在产生对应文档后创建。现有 `vue/` 路径暂时保留。

未来可按实际内容增加 `frontend/`、`backend/`、`ai/`、`engineering/`、`general/` 等领域目录，但本次不创建空目录。

## README 信息架构

README 按以下顺序组织：

1. 标题与一句话定位：“我的学习领地——由好奇心驱动，借助 AI 探索，最终由实践内化。”
2. 学习原则：说明 AI 负责拓展视野和生成初稿，用户负责判断、验证、实践与形成观点。
3. 知识地图：仅展示仓库内真实存在的领域和主题链接。
4. 学习看板：记录主题、领域、成熟度、最近更新日期和下一步行动。
5. 想法入口：链接至 `inbox.md`。
6. 文档标准：简述成熟度模型，并链接至 `KNOWLEDGE_GUIDE.md`。

首页以导航实用性为主，个人宣言保持简短，避免口号堆叠。

## 知识成熟度

每篇主题文档采用以下状态之一：

| 状态 | 含义 | 升级条件 |
| --- | --- | --- |
| `idea` / 💭 想法 | 只有问题或学习意图 | 已形成可研究的主题 |
| `ai-draft` / 🤖 AI 初稿 | AI 已协助整理，内容尚未由用户充分验证 | 完成必要的查证和实践 |
| `verified` / 🧪 已验证 | 关键结论经过资料或实践验证 | 用户能够独立解释和使用 |
| `internalized` / 🧠 已内化 | 用户能解释、应用，并理解边界和取舍 | 仍需按主题时效性复习 |

“已内化”不表示永久完成。版本敏感或持续变化的主题仍需定期复查。

## 文档元信息

主题文档使用精简 YAML 元信息：

```yaml
---
title: Vuex 与 Pinia
status: ai-draft
created: 2026-07-26
updated: 2026-07-26
reviewed: null
---
```

- `title`：清晰的主题名称。
- `status`：四级成熟度之一。
- `created`：首次建立文档的日期。
- `updated`：最后一次内容修改日期。
- `reviewed`：最后一次由用户复习或验证的日期；未复习时为 `null`。

本次为现有 `vue/vuex-pinia.md` 增加元信息，但不改写其正文。

## 人机协作与写作规则

AI 的职责：

- 帮助澄清问题、建立概念地图和发现知识盲点。
- 生成可编辑的初稿、例子、练习和查证线索。
- 对版本敏感内容标记目标版本和查证日期。
- 明确区分可验证事实、推论、建议和待验证内容。

用户的职责：

- 决定学习目标和文档真正需要回答的问题。
- 核验关键事实、运行技术示例并记录实践结果。
- 加入自己的理解、反例、取舍和使用边界。
- 决定文档是否能升级为“已验证”或“已内化”。

写作要求：

- 开头优先回答为什么值得学，以及本文具体解决什么问题。
- 篇章结构根据主题确定，不强制使用固定八段式。
- 优先保留关键问题、取舍、反例、踩坑记录和真实场景。
- 技术示例应尽量完整、可执行，并注明必要环境或版本。
- 允许明确写出“不确定”和“待验证”，不得用流畅表达掩盖证据不足。
- 引用资料时优先选择官方文档和一手来源。

## `tech-learning-guide` 的使用方式

`tech-learning-guide` 作为完整性检查表使用，而不是文章模板。生成技术学习文档时，可以参考其概念地图、学习计划、环境搭建、深入讲解、练习、生态、项目和资源等维度，但应：

- 只保留对当前主题真正有价值的部分。
- 不强求固定数量的概念、项目或资源。
- 避免每篇文章重复相同的标题和句式。
- 加入明确的作者判断、取舍理由和待验证问题。
- 将初始产物标记为 `ai-draft`。
