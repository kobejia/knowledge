# Personal Learn Skill 设计

## 背景

当前仓库通过 `EDITORIAL_GUIDE.md` 与 `READER_PROFILE.md` 分别保存编辑规则和个人画像。不同工具不一定主动读取或完整执行它们，而且规则、个人偏好与项目导航混在多个入口中，容易造成生成结果不一致。

本设计将文档生成能力收敛为仓库级 `personal-learn` skill：稳定的编辑规则由 skill 管理，个人差异由根目录配置管理，Markdown、Demo 和练习题规则按需加载。原有两份规范文件迁移完成后删除，不再保留并行规范源。

## 目标

- 仓库内创建或实质修改学习文档时，稳定触发同一套交互、生成和验证流程。
- 先理解用户输入并消除实质歧义，再由用户选择内容档位。
- 对技术主题分别确认是否需要 Demo 和练习题；非技术主题跳过该确认。
- 将个人画像抽离为 `personal-learn-config.yaml`，并提供预填当前画像的默认模板。
- 将稳定编辑原则迁入 skill，将 Markdown、Demo 和练习题规则拆成按需参考文件。
- 删除 `EDITORIAL_GUIDE.md` 与 `READER_PROFILE.md`，避免多个规范源漂移。
- README 只保留项目介绍，不再承担知识地图或编辑规范入口职责。
- 用基线测试和对照测试验证不同工具能遵循相同流程。

## 非目标

- 首版不建设博客、知识地图界面或 Markdown 浏览器。
- 不覆盖 Word、PDF、PPT、电子表格或其他二进制文档格式。
- 不在用户确认前为技术文档创建 Demo 或练习题。
- 不把所有内容强制改造成同一种章节模板。
- 不把稳定的编辑规则全部暴露成可任意组合的 YAML 开关。
- 不引入内容管理系统或全仓库构建流水线。

## 采用方案

采用“skill 编排 + 专项 references + 独立个人配置”：

```text
personal-learn-config.yaml

.agents/skills/personal-learn/
├── SKILL.md
├── assets/
│   └── personal-learn-config.template.yaml
├── references/
│   ├── editorial-policy.md
│   ├── markdown-quality.md
│   ├── demo-quality.md
│   └── exercise-quality.md
├── scripts/
│   ├── init-config.sh
│   └── validate-config.sh
└── evals/
    └── evals.json
```

`SKILL.md` 只负责触发、交互顺序、资源路由和完成条件。稳定内容规范进入 `editorial-policy.md`；格式与产物特有规则进入对应 reference；个人经验与偏好只存在于根目录配置及其默认模板。

## 触发范围

当任务在当前仓库内创建或实质修改以下内容时使用 `personal-learn`：

- 技术或非技术学习文档；
- 深度专题、概览、入门介绍和资料清单；
- 用户确认需要的 HTML、CSS、JavaScript Demo；
- 用户确认需要的技术练习题；
- 对上述产物进行扩写、重构或质量修订。

纯拼写修正、机械格式化或不改变语义的微小编辑可以不启动完整生成前交互，但仍需遵守相应文件的局部格式。

## 生成前交互

交互顺序不可跳过或交换。

### 1. 理解与消歧

先判断主题、目标和产物范围：

- 存在实质歧义时，例如主题边界不明确、存在多个合理方向或要求互相冲突，提供简洁、互斥的选项并等待用户选择。
- 不存在实质歧义时，用一至两句话介绍所理解的主题与目标，不要求用户设计目录。

### 2. 选择内容档位

理解一致后，请用户从四档中选择。配置中的推荐档位可以作为建议展示，但不能替代用户选择。

| 展示名称 | 内部标识 | 内容边界 |
| --- | --- | --- |
| 专家 | `expert` | 跳过常规入门，聚焦运行模型、架构演化、设计取舍、生产约束、失败模式和前沿问题。 |
| 入门 | `beginner` | 建立必要概念、基本用法和最小可用理解，不展开全面论证或高级边界。 |
| 全面 | `deep-dive` | 从必要基础逐步进入核心模型、证据、主要分歧、取舍、反例和现实边界。 |
| 了解 | `survey` | 建立视野地图，包含必要入门内容、主题组成、价值和关键问题，但不进入完整实现或全面论证。 |

### 3. 确认技术类附加产物

- 技术主题：分别确认是否需要 Demo、是否需要练习题，允许只选其一、两者都选或都不选。
- 非技术主题：跳过该步骤，直接进入生成。

## 配置设计

### 配置位置与生命周期

- 生效配置固定为仓库根目录 `personal-learn-config.yaml`。
- 默认模板固定为 `.agents/skills/personal-learn/assets/personal-learn-config.template.yaml`。
- skill 首次运行时先检查生效配置。
- 配置缺失时，说明将基于默认模板初始化，并运行 `scripts/init-config.sh` 生成根目录配置。
- 初始化后运行 `scripts/validate-config.sh`；校验失败则停止生成并给出具体字段错误。
- 已存在的配置不得被初始化脚本覆盖。更新模板也不得静默修改用户配置。

### 默认配置内容

默认模板预填当前画像：

```yaml
version: 1
language: zh-CN

learner:
  goal: 通过高质量知识文档扩展视野、增加知识深度并强化复杂系统分析能力
  experience:
    frontend_years: 10
  known_domains:
    - frontend
    - browser
    - javascript
    - web-engineering

level_recommendations:
  known_technical_domains: expert
  adjacent_technical_domains: deep-dive
  unfamiliar_domains: deep-dive
  quick_overview: survey
```

字段值用于调整起点和推荐档位，不能被解释为用户掌握了未明确列出的框架、语言、行业或项目经验。

### 配置与规则的边界

配置只保存个人差异：

- 输出语言；
- 学习目标；
- 已明确的经验与熟悉领域；
- 不同领域的推荐档位。

以下内容属于 skill 的稳定规则，不进入配置：

- 理解、消歧和档位选择顺序；
- 四档的正式语义；
- 问题优先、模型优先、证据、取舍、反例和边界要求；
- 来源质量和事实表达规则；
- Markdown、Demo 与练习题的质量门槛；
- 验证和完成声明规则。

## 现有规范迁移

### 迁入配置模板

从 `READER_PROFILE.md` 迁入：

- 学习目标；
- 10 年前端经验；
- 已明确的领域背景；
- 熟悉、相邻和陌生领域的推荐档位。

### 迁入 `editorial-policy.md`

从 `EDITORIAL_GUIDE.md` 与 `READER_PROFILE.md` 迁入：

- 问题先于术语、模型先于细节；
- 设计动因、演化、取舍、边界、反例和失败模式；
- 技术与非技术主题的研究重点；
- 事实、主流解释、推论、争议和未知的区分；
- 来源优先级、就近引用和时效性说明；
- 结构与篇幅自适应、避免模板化和基础重复；
- 四档内容深度的正式定义；
- 不虚构用户背景和观点的约束。

### 迁入专项 references

- Markdown 元信息、标题、链接、代码块、表格与引用检查迁入 `markdown-quality.md`。
- Demo 的目标、最小结构、运行验证与正文一致性迁入 `demo-quality.md`。
- 练习题的覆盖、难度、答案和知识迁移要求迁入 `exercise-quality.md`。

### 删除原文件

迁移及对照检查完成后删除：

- `EDITORIAL_GUIDE.md`
- `READER_PROFILE.md`

删除前必须逐项核对原有有效规则已进入配置模板或 skill reference。不得为减少篇幅而丢失事实、来源、边界或禁止事项。

## README 边界

README 只保留：

- 项目名称；
- 一至数段项目定位与目标介绍；
- 必要时说明内容由 `personal-learn` 协助生成。

README 删除：

- 知识地图与逐篇文档链接；
- 编辑规范摘要；
- 对已删除规范文件的引用；
- skill 的完整使用手册。

博客与可视化知识地图明确延期，不属于本轮实现。

## Skill 工作流程

1. 判断是否触发 `personal-learn`。
2. 检查根目录配置；缺失时从默认模板初始化并校验，存在时直接校验。
3. 读取配置，理解用户输入；存在实质歧义时给出选项，否则用一至两句话介绍理解。
4. 展示四档及基于配置的推荐，请用户选择。
5. 判断主题是否为技术类；技术类分别确认 Demo 和练习题，非技术类跳过。
6. 读取 `editorial-policy.md`、`markdown-quality.md` 和目标文件上下文。
7. 仅当用户选择 Demo 时读取 `demo-quality.md`。
8. 仅当用户选择练习题时读取 `exercise-quality.md`。
9. 为时效性事实、专业结论和争议性判断查阅一手或权威来源。
10. 按所选档位生成或修改 Markdown；按用户选择生成附加产物。
11. 验证 Markdown、引用和链接；如有 Demo，实际运行或浏览器验证；如有练习题，检查答案与正文覆盖。
12. 复查正文、Demo 和练习题的概念、术语、前提及边界一致性。
13. 说明实际验证范围和未验证部分，不做无证据的完成声明。

## 专项规则边界

### `editorial-policy.md`

保存跨格式、跨主题稳定成立的内容质量原则和四档定义。它是内容规范的唯一事实来源，不包含个人画像或仓库文件路径清单。

### `markdown-quality.md`

保存 YAML 元信息适用范围、标题层级、列表、表格、代码块、相对链接、引用邻近性及机械检查规则。不要求所有 Markdown 使用同一章节模板。

### `demo-quality.md`

只在技术主题且用户选择 Demo 时加载。Demo 必须对应正文中的明确学习或验证目标，保持 HTML、CSS、JavaScript 职责清楚，并验证启动、控制台、关键交互和必要视口。无法验证时必须披露。

### `exercise-quality.md`

只在技术主题且用户选择练习题时加载。题目必须匹配所选档位，覆盖正文关键概念并提供可核对的答案、解析或评价标准，不考查正文未覆盖的偶然细节。

## 错误与不确定性处理

- 配置不存在：从模板初始化，不覆盖其他文件。
- 配置已存在但无效：停止生成，报告字段路径和期望值，不回退到静默默认值。
- 会改变主题方向或产物范围的信息缺失：先消歧。
- 仅缺少不影响方向的次要信息：采用最小合理假设并明确记录。
- 无法获得可靠来源：缩小结论或标记未确认，不补造事实。
- Demo 无法启动或验证失败：报告失败证据，不宣称完成。
- 目标文件有未提交修改：保留用户改动，不覆盖无关内容。

## 测试策略

skill 按 RED-GREEN-REFACTOR 创建：先在没有 skill 的情况下运行真实任务提示并记录遗漏，再创建最小 skill 复测，最后针对新漏洞补强。

首轮场景：

1. 根目录无配置时触发任务，检查是否从模板初始化、保留预填画像并完成校验。
2. 根目录存在无效配置时触发任务，检查是否停止并指出具体错误，而不是静默使用默认值。
3. 输入明确的前端主题，检查是否用一至两句话介绍理解、推荐专家档但仍等待用户选择。
4. 输入存在多个合理方向的主题，检查是否先提供互斥选项消歧。
5. 用户选择“了解”，检查文档是否建立视野地图并包含必要入门内容，但未进入全面论证。
6. 技术主题选择 Demo 与练习题，检查是否按需加载规则、实际验证 Demo、提供可核对答案并保持三类产物一致。
7. 技术主题拒绝附加产物，检查是否没有自行创建 Demo 或练习题。
8. 非技术主题选定档位后，检查是否跳过 Demo 与练习题确认。
9. 迁移对照检查，确认原两份规范中的有效规则均有新归属，且 README 不再包含知识地图和规范链接。

客观检查覆盖配置 schema、初始化幂等性、文件存在性、元信息、链接、Demo 可运行性和练习题答案完整性；人工评审覆盖模型质量、取舍、边界、信息密度以及正文、Demo 与练习题的一致性。

## 完成标准

- `.agents/skills/personal-learn/SKILL.md` 可被项目级发现，frontmatter 覆盖学习文档、Markdown、Demo 和练习题等触发语境。
- 根目录 `personal-learn-config.yaml` 已由默认模板生成并通过校验，模板预填当前画像。
- 配置与 skill 规则职责清楚，推荐档位不会替代用户选择。
- 生成前稳定执行“理解或消歧 → 用户选择档位 → 技术类确认 Demo 与练习题”。
- `EDITORIAL_GUIDE.md` 与 `READER_PROFILE.md` 的有效内容完成迁移后被删除。
- README 只保留项目介绍，不再包含知识地图或规范入口。
- Markdown、Demo 与练习题规则按需加载且互不冲突。
- 无 skill 基线已经记录；加入 skill 后关键遗漏得到纠正。
- 初始化、校验和机械检查通过，人工判断项及未验证部分有清晰记录。
